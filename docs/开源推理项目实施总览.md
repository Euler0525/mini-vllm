# 开源推理项目实施总览

最终交付是在当前仓库持续维护的 **mini-vllm 与推理评测工具集**。前者实现可解释、可测试的推理运行时，后者支持统一输入、服务测量、性能诊断与结果复现。vLLM 是对照后端和源码参照。两部分共享模型、负载与报告，不要求拆成两个仓库。求职展示从项目中提取已验证的工程成果。

本文把 [学习与求职计划](vLLM学习与求职计划.md) 展开成按依赖推进的操作手册。总投入约 240–300 小时，examples 实践计入其中；安装、下载和额外硬件准备另计。所有手册按功能命名，进度以验收产物判断。

## 当前起点与交付边界

当前已有 Qwen2.5 前向、权重加载、连续 KV Cache、单请求生成、逻辑 block 管理和三后端离线对照工具。`KVCache.length` 是整个 batch 共用的标量；现有 `Sequence` 只有 waiting/running/finished 三种状态；`BlockManager` 尚未接入物理 KV。这些限制需要通过后续实现解除，不能在 README 中提前写成已支持多请求与分页 attention。

| 交付部分 | 必须具备的能力 | 可选扩展 |
| --- | --- | --- |
| 推理运行时 | 保留单请求 oracle；动态到达、连续批处理、取消与资源回收；分页 KV 参考 attention；一个有正确性验证的 Triton 算子及显式回退 | mini_llm 前缀共享、分页 attention kernel、自有 graph runner、TP |
| 推理评测工具集 | 固定输入与元数据；流式客户端；到达时序回放；容量扫描；metrics 对齐；结果汇总与图表；vLLM 调优配置 | 量化、额外任务模型、真实多卡与网络 connector |
| 公开材料 | 安装说明、架构图、CPU/GPU 测试边界、经验证的性能报告、贡献说明、许可证、发布清单 | 上游贡献、独立网页与托管服务 |

Triton 实验可以得出无显著收益，验收要求是测量可靠、有支持范围与回退。量化、LoRA、多模态和真实多卡不阻塞单卡版本；明确记录资源限制和未完成部分。vLLM APC、投机解码、顺序 KV 交接仍需按手册完成验证，作为评测工具集的实验案例。

## 手册使用约定

所有命令默认在 `~/Desktop/mini-vllm` 执行；每段 shell 命令写明目录。HF/mini_llm 使用 `.venv/bin/python`，vLLM 使用 `~/Desktop/vllm/.venv/bin/python` 或 `../vllm/.venv/bin/vllm`。Python 使用不含 `../` 的环境路径，避免 Python 3.14 的环境前缀警告。模型链接是 `artifacts/models/qwen2.5-0.5b`，完整 snapshot 为 `7ae557604adf67be50417f59c2c2f167def9a775`，vLLM 参照 commit 为 `bfdbfa1632ef638db7d201f366c6f46cc26ca2b6`。

手册中的“现有命令”调用当前仓库或上述 vLLM 快照中的接口。“待开发”表格是需要实现的契约，路径只有实现并通过验证后才存在；不提供可直接执行的虚构入口。命令和代码块是后续操作步骤，本次补全文档没有执行 GPU 实验，也没有生成性能结论。

正式测试前检查安装版本的 `--help` 与启动日志，保存实际 backend、runner、默认参数及降级行为。更换源码或模型 revision 后，先重新做正确性和配置校验。8GB 单卡依次运行模型实例；APC 冷热状态、编译缓存冷热状态和热机状态分别记录。

## 开发拆分与版本目标

按可独立审查的变更推进，每项包含实现、适用测试和使用说明。不要把所有学习笔记塞进一次大改动。

| 版本目标 | 建议变更顺序 | 对外可展示的行为 |
| --- | --- | --- |
| 正确性与测量基础 | 固定输入 → 结果 schema → 流式客户端 → 引擎事件 | 同一请求可以跨后端对照，测量边界明确 |
| 动态运行时 | 确定性 scheduler → 生命周期 → batch runner → 到达回放 | 短请求可以在长请求结束前加入，取消后可继续服务 |
| 分页运行时 | 物理布局 → 映射与回收 → 参考 attention → 边界回归 | 不同长度请求共享物理 KV 池且相互隔离 |
| 可解释优化 | trace → Triton → 编译/graph → SLO 扫参 | 每个开关有正确性、成本和负载适用范围 |
| 首个公开版本 | CI → 包构建 → 文档 → 独立复现 → 发布说明 | 新读者可以安装、运行小例子并复现一个结论 |

发布版本号由实际完成情况决定，不能把时间经过等同于功能完成。早期可公开开发中的仓库，但 README 必须列出已实现、实验性和计划中能力。

## 统一实验与报告契约

每次运行保存 `run_id`、时间、仓库 SHA 和 dirty 状态、vLLM SHA、模型完整 revision、依赖清单、硬件/功耗条件、配置副本、输入 SHA256、seed、预热、重复次数、成功/失败/取消数、原始结果路径。多配置对照采用相同输入与到达序列，至少三次独立运行并交替顺序。小样本只报告范围或中位数，不作稳定 P99 的承诺。

| 路径 | 内容 |
| --- | --- |
| `mini_llm/engine/`、`mini_llm/kernels/` | 自有运行时与算子实现 |
| `benchmarks/inference/` | 负载、回放、采集、汇总与绘图工具 |
| `configs/inference/` | 服务、监控与实验配置 |
| `examples/vllm/<feature>/` | 独立改写、附来源说明的最小实例 |
| `artifacts/inference/<topic>/<run_id>/` | 输入、配置副本、日志、结果和 trace，本地保留 |
| `docs/reports/` | 实测后才添加的结论、精简数据表与复现步骤 |

待开发工具统一要求 `--help`、显式输入输出路径、拒绝意外覆盖、校验输入、非零失败退出码和机器可读结果。汇总工具遇到条件不一致应拒绝直接算加速比。失败请求保留在分母和报告中；客户端、服务端与 GPU 时间来自不同观察点，不能直接相减成精确分阶段耗时。

报告至少包括问题、假设、配置、测量边界、正确性证据、结果与离散度、反例、限制、复现命令。发布只引用验证过的数字；大 trace 和权重不提交到 Git，公开精简汇总及获取原始证据的方法。
